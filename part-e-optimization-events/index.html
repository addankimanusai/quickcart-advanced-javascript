Conceptual Reference & Question Answers (Parts E) Evaluated

1. Debouncing vs Throttling

Q1: What is the difference between debouncing and throttling?

Debouncing delays execution until a specified quiet period (delay) has passed since the last event trigger; any new event resets the timer. Throttling guarantees that a function executes at a steady maximum rate of at most once per specified time window, regardless of how frequently events occur.

Q2: Which suits search suggestions?

Debouncing suits search suggestions because you only want to issue an expensive network/database query once the user has paused or finished typing their keyword.

Q3: Which suits scroll and resize events?

Throttling suits continuous events like scrolling, viewport resizing, or drag-and-drop, where continuous visual updates (e.g. progress indicators, infinite scroll) need regular, bounded execution without stuttering the browser main thread.

2. Memoization & Closures

Q1: What is memoization?

Memoization is an optimization technique that caches the return values of expensive, pure function calls based on their input arguments, allowing subsequent calls with the same inputs to return immediately from cache.

Q2: How does it improve performance?

It eliminates redundant CPU computations and reduces runtime complexity from exponential or linear to O(1) constant-time lookup for repeated argument sets.

Q3: What role do closures play?

Closures enable the outer memoize function to create a private, persistent cache object or Map in its lexical scope. The returned inner function retains lexical access to this private cache across invocations without exposing it as a global variable.

3. Event Bubbling & Delegation

Q1: What is event bubbling?

Event bubbling is the phase in the DOM event propagation lifecycle where an event triggers first on the deepest target element and then bubbles upwards through its ancestor hierarchy until it reaches document and window.

Q2: What is event delegation?

Event delegation is a design pattern where a single event listener is attached to a shared ancestor element rather than attaching individual listeners to every descendant child element, leveraging event bubbling.

Q3: Why is delegation useful for dynamically created elements?

Because newly created DOM elements do not require manual listener attachment; any dynamically added child automatically bubbles its events to the preexisting parent listener.

Q4: What does event.stopPropagation() do?

It halts the propagation of the active event through the DOM tree, preventing it from bubbling up to parent ancestor listeners or traveling down during capture.

Q5: Difference between event.target & event.currentTarget?

event.target is the actual, innermost DOM element that originated the event (e.g., the clicked button). event.currentTarget is the element that owns the currently executing event listener (e.g., the parent container).
